Stack Técnico

Todo el proyecto funciona como archivos estáticos desplegados en GitHub Pages — sin servidores, sin compilación, sin gestores de paquetes. Inspirado en la arquitectura de replicube.com y reimplementado de forma independiente.

▲
THREE.JS
Renderizador 3D WebGL. Usa InstancedMesh para renderizar vóxeles en batch por color con un máximo de 16 draw calls, y raycasting en tiempo real para detección de hover.
WebGL · r128
◈
FENGARI
Intérprete completo de Lua 5.3 compilado a WebAssembly. El usuario escribe Lua real — no un subconjunto — ejecutado de forma segura en un entorno aislado en cada ejecución.
Lua 5.3 · WASM
⬡
CANVAS 2D
Arquitectura de doble canvas: Three.js renderiza los vóxeles mientras un canvas superpuesto transparente dibuja las anotaciones de ejes, etiquetas de coordenadas y tooltips.
Canvas API
○
VANILLA JS
Sin frameworks, sin herramientas de compilación. ES6 puro con separación limpia entre paleta, motor y UI — desplegable como archivos estáticos en cualquier sitio.
ES6 · No Build

Qué Implementé

El concepto original es de Replicube. Estas son las piezas técnicas que tuve que construir para reproducirlo en el navegador, más las extensiones propias que añadí.

-- Replicube: recibe (x, y, z) → devuelve índice de color (1-16)
local d = sqrt(x*x + y*y + z*z)
if inrange(d, 4, 6) then return GREEN end

-- Replipaint: recibe (x, y) → devuelve índice de color
fill(BLACK)
return (floor(sqrt(x*x + y*y) / 6) % 16) + 1
01 ——
RENDERIZADO INSTANCIADO
Los vóxeles se agrupan por color en objetos InstancedMesh. Una escena con 15.000 vóxeles usa solo 16 draw calls — uno por color de paleta.
02 ——
SANDBOX DE LUA
Cada ejecución crea un estado Lua de Fengari desde cero. El código de usuario recibe helpers matemáticos, constantes de color y un print() aislado — nada más.
03 ——
MODO DUAL
Replicube mapea coordenadas 3D a vóxeles. Replipaint mapea coordenadas 2D a píxeles en un canvas infinito desplazable. Mismo modelo de scripting, distintas dimensiones.
04 ——
ANOTACIONES EN VIVO
Las marcas de ejes, etiquetas de coordenadas y tooltips se dibujan en un canvas superpuesto transparente, proyectados con precisión desde el espacio 3D al espacio de pantalla.
05 ——
PLANOS DE CORTE
Los sliders de corte X, Y, Z ocultan vóxeles más allá de un umbral, permitiendo seccionar una estructura e inspeccionar su interior sin modificar el código.
06 ——
EXPORTAR / IMPORTAR PROPIO
Funcionalidad añadida respecto al original: exporta el sketch como JSON con código y tamaño de grid, e impórtalo para restaurar el estado exacto — sin cuentas, sin servidores.

Retos de Implementación

Reproducir el comportamiento de Replicube sin acceso a su código fuente implicó resolver estos problemas técnicos desde cero.

Raycasting en meshes instanciados
El raycasting de Three.js devuelve un instance ID al impactar un InstancedMesh, no una clave de vóxel. El motor mantiene un Map<InstancedMesh, entry[]> paralelo para traducir el ID a coordenadas de mundo en O(1).
Puente Lua ↔ JS
Fengari expone una API de pila al estilo C de Lua. Pasar coordenadas y color desde Lua a JS requirió inyectar una función C personalizada (_jscell) como global de Lua, leyendo los argumentos de la pila por posición desde un closure JS.
Proyección de anotaciones
Las etiquetas de los ejes se posicionan encontrando la arista del bounding box más visible para la cámara en cada frame. Esto evita que aparezcan dentro del modelo proyectando los 4 puntos medios candidatos y eligiendo el más alejado del centro de la vista.
Canvas infinito de Replipaint
El modo 2D recalcula la ventana de coordenadas de mundo visible en cada desplazamiento o zoom, y re-ejecuta la función Lua solo para los píxeles visibles. Esto mantiene el conteo de píxeles acotado sin importar cuánto se desplace el usuario.
